# Codex 工作台治理

## 分层

| 层 | 只负责 |
| --- | --- |
| 全局 `D:\CodeX\.codex\AGENTS.md` | 跨项目长期安全边界和路由条件 |
| 项目/嵌套 `AGENTS.md` | 当前仓库真实结构、命令、代码锚点、配置定位和例外 |
| `schema/projects.yaml` | 项目身份、路径、能力与知识入口 |
| 项目页 | 长期状态、Runbook、已验证结论和历史决策 |
| agentMemory | 可复用的项目级根因、命令和验证结果 |
| Skill | 可重复的确定流程、脚本、模板和检查清单 |
| Plugin/MCP | 只有任务需要的外部能力与事实读取 |
| Codex 任务历史 | 一次执行证据；不是长期规则的唯一存放处 |

同一规则只保留一个权威正文，其他位置使用链接或“何时读取”的短路由。

## 新项目或新任务

1. 使用 `project-bootstrap` 确认路径、最近 AGENTS、Registry、项目页与项目记忆
2. 只加载当前任务需要的 Skill、CodeGraph、MCP 或插件
3. 未登记项目先按仓库事实工作，不虚构 Registry、项目页或记忆；确认长期维护后再登记
4. Registry 或项目页疑似漂移时运行 `project-doctor`，不在业务改动中顺手大规模修复治理文件

## 插件和 MCP

- “已安装”不等于“每次启用”；按任务能力选择，避免启动无关认证和外部访问
- 当前未安装的 Atlassian、Box、Calendar、Notion、SharePoint、Teams 等连接器不因治理工作自动安装
- 只有用户任务明确需要对应外部系统，且本地 Skill/MCP/现有插件无法完成时，才提出连接或安装
- 项目记忆优先使用 Registry 映射的 `agentmemory_*`；数据库 MCP 默认按登记权限使用
- 插件、MCP、Skill 的重复项以“能力是否等价、是否仍有项目依赖、最后成功验证时间”判断，不按目录名直接删除

## 能力状态刷新

Registry 的 `agentmemory_status` 和 `codegraph_status` 只说明对应**本地能力**在 `last_capability_review` 当日是否可用；它们不证明构建、接口、数据库或远端 Nacos 当前正常，后者仍按项目验证状态和事实源处理。

1. CodeGraph：先执行 `codegraph status <项目路径>`；只有索引目录已被忽略且已记录 `git status` 时，才对有 pending change 的项目执行 `codegraph sync`。未初始化且 `.codegraph/` 未被忽略时标记 `needs-review`，不通过改 `.gitignore` 或初始化来掩盖现有工作区状态。
2. agentMemory：检查 Registry 服务名与数据目录，并以一次 MCP `initialize`、`tools/list` 和 `memory_stats` 只读调用核验可达性；目录 mtime 不能代替内容时效，也不因服务可用而重写项目记忆。
3. Vault/Obsidian：先运行 `Test-CxMVault.ps1 -NoWrite`；插件以 `.obsidian/community-plugins.json` 和各 `manifest.json` 为准，workspace、recent files 和插件标签页只属于 UI 状态，不作为知识事实或迁移对象。
4. 已配置但未登记的项目记忆服务保留为 legacy/伴随工作区能力；只有明确长期维护价值、路径和项目页后才进入 Registry，避免把历史目录伪装成活跃项目。

## Nacos 项目

- 远端当前 namespace/group/dataId 是运行事实源
- 仓库模板用于定位、初始化与差异对照，客户端 snapshot/cache 用于恢复
- 普通启动与诊断只授权读取；发布、导入、初始化、覆盖或回滚需要精确目标的单独授权
- 写入前必须导出现有远端内容、核对来源和跨项目残留、生成脱敏差异并准备回滚
- 自动化和项目引导不得执行 Nacos 写操作

## 历史任务

- 成功完成、无待处理动作的自动化运行和一次性诊断任务可以归档
- 当前任务、置顶任务、失败任务、等待用户输入、待发送或需要复查的任务不得归档
- 归档使用 Codex 的可恢复归档能力，不删除 session 文件或直接改内部数据库
- 长期有价值的结论必须先进入项目页、operation、Skill 或项目记忆，再归档原任务

## 周期复盘与防错闭环

### 任务归档判定

默认在每周整理时处理超过 7 个自然日的任务；用户指定更短或更长的保留期时以用户要求为准。每条待归档任务必须同时满足：

1. 非当前任务、非置顶，且不包含“继续处理”、待用户输入、待发送、待复查或失败状态
2. 通过 `read_thread` 确认最后一轮已有最终交付或可核对的完成结论；列表中的 `idle`、`notLoaded` 仅用于筛选，不是完成证据
3. 可复用结论已经落到下表规定的载体，或确认为一次性内容

`interrupted` 不等于已完成；即使任务较旧也保留，待下次运行成功闭环后再归档。归档后重新盘点任务列表，确认仅归档目标任务；归档可恢复，不删除 session 文件、内部数据库或自动化状态。

### 归档副本的回收

归档不等于永久删除。仅当用户明确要求释放归档副本时，才允许回收满足以下条件的自动化运行记录：

1. 以 JSONL 的**首条** `session_meta` 为会话身份和来源；子任务文件可能嵌入父任务元数据，后续 `session_meta` 不得用于分类
2. 主来源为 `automation`，从实际用户任务消息提取自动化 ID；不得从系统提示、工具说明或完整原始文本模糊匹配
3. 同一自动化保留最新一份归档，并保留被 `MEMORY.md` 或长期复盘引用的历史证据
4. 删除前对精确路径、归档根目录、候选数量、文件大小和 SHA-256 逐项核验；不一致立即停止
5. 优先移入 Windows 回收站，验证源文件已移除并记录数量、大小、保留规则和恢复方式

子任务、项目实施、设计审查和排障链即使已归档，也不因“体量大”或“标题相近”批量删除；只有父任务、项目页/Runbook 和必要证据均已独立承接后，才逐组单独评估。

### 重复错误的防护栏

| 易错点 | 固定动作 | 验证信号 |
| --- | --- | --- |
| 工具参数或返回结构靠猜测 | 调用前查看 schema；首次调用先输出实际对象的最小摘要，再按真实字段解析 | 不假设 `content`、分页或上限参数；参数校验一次通过 |
| 历史、记忆或本地模板被当成当前事实 | 启动时按 `project-bootstrap` 读取当前规则和仓库；Nacos 先读精确远端目标 | 结论标明来源、读取时间和“已验证/未验证”状态 |
| 为解决一个问题扩大修改范围 | 先读最近 AGENTS、`git status` 与上下游；已有用户改动只绕开，不覆盖 | 最终 diff 只含用户授权范围，未顺手格式化或重构 |
| Windows 脚本与中文编码问题 | 复杂 PowerShell 写入项目 `.tmp` 并语法预检；双击 `.cmd` 保持 ASCII 包装入口 | 预检通过，实际路径与运行时版本读回有效 |
| 浏览器或控制通道一次超时就判定页面失败 | 只做一次干净重连；仍失败则切换到后端、API、数据库或本地 harness 证据 | 明确区分“控制通道失败”和“业务页面失败” |
| 自动化先写已发送/已完成状态 | 先校验产物与所有实际动作成功，再提交 `mark-sent` 或等价状态 | 产物、发送结果和状态提交三者可追溯且顺序一致 |

### 结论落位

| 内容 | 权威位置 |
| --- | --- |
| 跨项目可重复流程、检查清单和任务归档规则 | `wiki/operations/`；流程高度确定且需要脚本/模板时再升级为 Skill |
| 跨项目短硬约束或触发条件 | 全局 `D:\CodeX\.codex\AGENTS.md`，正文链接到 operation 或 Skill |
| 项目架构、运行入口、长期决策和 Runbook | 对应 `wiki/projects/<project>.md` |
| 项目级根因、检索词、命令与已验证结果 | 对应 `agentmemory_*`；不写跨项目泛化规则或敏感信息 |
| 一次执行过程、截图、完整对话和临时推理 | Codex 任务历史，仅作审计与恢复 |

新项目或新对话只需通过 `project-bootstrap` 读取入口规则、Registry、项目页和命中的项目记忆；不要求重放历史对话。

## 清理与归档

按“盘点 → 归属 → 备份/可恢复归档 → 验证 → 删除”执行：

1. 活跃配置、当前插件版本、业务文件、凭据、浏览器数据和用途不明目录只报告
2. session 历史优先用任务归档，不直接删除
3. 插件安装残留、临时目录和旧备份先证明没有当前引用，再移动到带日期的隔离区
4. 隔离期后仍要永久删除时，必须再次确认精确目标
5. 每次清理记录前后数量、大小、路径、恢复方式和验证结果
