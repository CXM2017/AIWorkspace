# 新知识库搭建与验收 Runbook

## 结论

下次新建知识库时，不要只创建目录骨架。必须一次性完成：方法论选型、Obsidian 配置迁移、使用说明、采集消化复盘闭环、模板、健康检查和复盘沉淀。

## 适用场景

- 新建个人知识库
- 从旧 Obsidian vault 迁移到新 vault
- 为不同 agent 搭建中立 Markdown 知识库
- 需要迁移插件、主题、模板和旧项目记忆

## 标准流程

1. 明确边界
   - 目标路径
   - 是否覆盖个人、项目或全生活知识
   - 旧库只读保留还是完整迁移
   - 哪些旧记忆必须桥接
2. 盘点旧库
   - Markdown 数量
   - 项目数
   - Obsidian 插件和主题
   - `.tmp`、workspace、recent files、agent 状态目录
3. 先建人用入口
   - `00-开始使用.md`
   - `README.md`
   - `wiki/index.md`
   - `wiki/overview.md`
4. 再建机器契约
   - `schema/AGENTS.md`
   - agent adapter 只做薄入口
   - 页面 frontmatter 契约
5. 建日常闭环
   - `raw/inbox/`
   - `reviews/daily/`
   - `reviews/weekly/`
   - `reviews/monthly/`
   - `templates/`
6. 迁移 Obsidian 配置
   - 复制插件、主题、icons 和必要 JSON
   - 清空 workspace、recent files、Claudian 会话状态
   - 设置 Daily Notes 和 Templates
   - 隐藏 `.claude/`、`.claudian/`、缓存和构建目录
7. 建 legacy bridge
   - 旧 vault 来源索引
   - agentMemory 桥接索引
   - 重点项目桥接页
8. 更新外部 AGENTS 桥接
   - 更新全局 `D:\CodeX\.codex\AGENTS.md`
   - 更新相关工作区 `AGENTS.md`
   - 明确新主库路径
   - 明确旧库只读或 legacy source 定位
   - 明确新知识默认写入位置
9. 更新 Agent 入口和 Skill
   - 扫描 `D:\CodeX\.codex\skills` 中硬编码旧 vault 的 `SKILL.md`
   - 将默认读取、写入、日记、runbook 和自动化沉淀位置改到新 vault
   - 旧 vault 路径只能保留为 legacy fallback，并写清触发条件
   - 对已经打开的旧线程发送纠偏提示，要求重新读取当前工作区 `AGENTS.md` 和新 vault 入口
10. 写健康检查
   - 结构完整
   - frontmatter 和 H1
   - wikilink 断链
   - 不可见控制字符
   - PowerShell 反引号退化文本
   - 敏感信息模式
   - Obsidian 插件、主题和状态污染
11. 跑验收
   - 健康检查必须 `pass`
   - error 和 warning 必须为 0
   - 人打开 Obsidian 时第一屏能看到使用说明

## 本次踩坑

- PowerShell 双引号 here-string 中的 Markdown 反引号会触发转义，导致路径文本丢失首字母，例如 `raw/` 和 `tools/` 被破坏
- 只跑结构检查不够，必须检查不可见控制字符和退化文本
- Obsidian 的 `workspace.json`、recent files、Claudian data 会把旧状态带进新库，不能直接全量复制
- 只有目录没有 README 时，Obsidian 侧栏看起来仍然混乱
- 只写 agent 契约不够，人用入口必须清楚回答“新文章、网页、截图放哪里”
- 健康检查一开始没有 wikilink 断链检查，必须补进脚本
- 只更新新 vault 不够，全局和相关工作区 `AGENTS.md` 仍可能指向旧库，其他线程会继续读旧库
- 只更新 `AGENTS.md` 仍不够，已安装 Skill 也可能硬编码旧 vault，例如日记、自动化、启动 runbook
