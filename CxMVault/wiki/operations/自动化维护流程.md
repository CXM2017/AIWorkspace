# 自动化维护流程

## 结论

CxMVault 使用四个 Codex 本地自动化：技术雷达、每日消化、每周整理、每月复盘。自动化负责调度、扫描、状态和通知；人工分诊与闭环规则只引用 [[采集消化复盘SOP]]。

## 运行时间

- `cxmvault-4`：每天 08:30，技术雷达采集与热点报告
- `cxmvault`：每天 17:00，Daily pending 扫描
- `cxmvault-2`：每周五 17:00，Review backlog 与周复盘
- `cxmvault-3`：每月最后一天 17:00，月度结构复盘

## Runner 与状态

入口：

```powershell
& 'D:\CodeX\.codex\automations\cxmvault-maintenance\scripts\run-cxmvault-maintenance.ps1' -Mode daily
& 'D:\CodeX\.codex\automations\cxmvault-maintenance\scripts\run-cxmvault-maintenance.ps1' -Mode weekly
& 'D:\CodeX\.codex\automations\cxmvault-maintenance\scripts\run-cxmvault-maintenance.ps1' -Mode monthly
& 'D:\CodeX\.codex\automations\cxmvault-tech-radar\scripts\run-cxmvault-tech-radar.ps1' -Mode run
```

维护输出目录为 `E:\AIWorkspace\CxMVault\outputs\automation\cxmvault-maintenance\`，关键文件：

- `run-result.json`：本次摘要、`pending_count`、`review_backlog_count`、`overdue_review_count`、健康检查和人工判断项
- `run-log.jsonl`：追加式运行日志
- `state.json`：已处理来源的 hash、mtime 与状态

两个待办池不可混为一谈：

- Daily pending：缺少状态、`processing_status: inbox` 或 `compile_decision: unreviewed`
- Weekly backlog：`processing_status: review` 或 `compile_decision: weekly-review`

Daily pending 为 0 不代表 Weekly backlog 已清空。

自动化配置位于：

- `D:\CodeX\.codex\automations\cxmvault\automation.toml`
- `D:\CodeX\.codex\automations\cxmvault-2\automation.toml`
- `D:\CodeX\.codex\automations\cxmvault-3\automation.toml`
- `D:\CodeX\.codex\automations\cxmvault-4\automation.toml`

## Tech Radar

Tech Radar 抓取公开 RSS/Atom 与 GitHub 候选，先写入 `raw/inbox/web/`，再由后续流程决定是否编译。三榜分别评分，每榜最多 10 条且不为凑数降低阈值；三榜均无热点时不发邮件。本机已安装 Skill 不重复采集。

输出目录为 `outputs/automation/cxmvault-tech-radar/`，关键文件为 `run-result.json`、`report-result.json`、`pending-send.json`、`run-log.jsonl` 与 `state.json`。邮件仍按“一位收件人一封，全部发送成功后才 mark-sent”的可靠性规则执行。

## Daily、Weekly、Monthly

- Daily：只处理 Daily pending；无 pending 且健康通过时静默记录
- Weekly：处理 Review backlog，更新 `reviews/weekly/YYYY-Www.md`，把重复流程提升为项目规则、operation 或 Skill
- Monthly：检查项目登记、legacy bridge、agentMemory 路由、断链、过期结论和结构膨胀

每次运行完成后再次扫描并执行健康检查；失败时保留状态文件，不把未完成任务标记成功。

## 通知与历史任务

- 无变化且健康通过：静默
- 有新沉淀：简短汇报文件与数量
- 失败、高风险、敏感信息或无法归类：提示人工处理
- 自动化成功完成且无待处理动作时，可归档该次 Codex 任务；失败、等待用户或待发送状态不得自动归档
- 归档是可恢复的历史整理，不删除任务记录或运行状态

## 安全边界

- 不写旧 `E:\CodeXData\CodeXKnowledge`，不主动写项目 agentMemory
- 不写入或回显 Token、Cookie、Authorization、私钥、密码、完整连接串
- 不把高风险平台规避教程编译成可执行 SOP
- 自动化不得发布、导入、初始化或覆盖 Nacos；只读诊断也必须按项目规则解析精确目标并脱敏
