# 自动化维护流程

## 结论

CxMVault 使用四个 Codex 本地 cron 自动化维持自学习闭环：技术雷达采集、每日消化、每周整理、每月复盘。自动化允许写入 `E:\AIWorkspace\CxMVault`，但旧 `CodeXKnowledge` 和 `agentMemory` 默认只读。

## 运行时间

- `cxmvault-4`：每天 08:30，采集公开技术资讯、热门 GitHub 项目和 Skills/插件候选并写入 `raw/inbox/web/`
- `cxmvault`：每天 17:00，检查 `raw/inbox/` 是否有未处理内容
- `cxmvault-2`：每周五 17:00，梳理本周 daily、inbox、wiki/log 和健康报告
- `cxmvault-3`：每月最后一天 17:00，做月度复盘、旧库桥接检查和结构优化

## Runner

入口：

```powershell
& 'D:\CodeX\.codex\automations\cxmvault-maintenance\scripts\run-cxmvault-maintenance.ps1' -Mode daily
& 'D:\CodeX\.codex\automations\cxmvault-maintenance\scripts\run-cxmvault-maintenance.ps1' -Mode weekly
& 'D:\CodeX\.codex\automations\cxmvault-maintenance\scripts\run-cxmvault-maintenance.ps1' -Mode monthly
& 'D:\CodeX\.codex\automations\cxmvault-tech-radar\scripts\run-cxmvault-tech-radar.ps1' -Mode run
```

输出目录：

```text
E:\AIWorkspace\CxMVault\outputs\automation\cxmvault-maintenance\
```

关键文件：

- `run-result.json`：本次运行摘要、pending 列表、健康检查结果、人工判断项
- `run-log.jsonl`：追加式运行日志
- `state.json`：已处理 raw source 的 hash、mtime 和状态

Codex 自动化配置：

- `D:\CodeX\.codex\automations\cxmvault\automation.toml`
- `D:\CodeX\.codex\automations\cxmvault-2\automation.toml`
- `D:\CodeX\.codex\automations\cxmvault-3\automation.toml`
- `D:\CodeX\.codex\automations\cxmvault-4\automation.toml`

## Tech Radar

Tech Radar 自动化是上游采集层，只负责从公开 RSS/Atom 来源和 GitHub Search 抓取候选、去重、打分并写入 `raw/inbox/web/`。高价值候选会在每日消化后沉淀到 [[../domains/AI Agent工程与工具生态雷达|AI Agent 工程与工具生态雷达]] 等领域页。

默认来源包括 Hacker News、GitHub Blog、OpenAI News、Google DeepMind Blog、Vercel Blog、Cloudflare Blog、阮一峰科技爱好者周刊、arXiv 分类 RSS，以及 GitHub 热门新仓库、活跃开发工具、AI agents、LLM apps、MCP、Codex/Claude Code Skills、Obsidian 插件、Java/Spring 项目。采集结果带有 `processing_status: inbox`、`risk_level: unreviewed` 和 `compile_decision: unreviewed`，不直接进入 `wiki/`。

输出目录：

```text
E:\AIWorkspace\CxMVault\outputs\automation\cxmvault-tech-radar\
```

关键文件：

- `run-result.json`：本次采集摘要、来源状态、候选数量、新增 raw 文件
- `run-log.jsonl`：追加式运行日志
- `state.json`：已采集条目的 ID 和 URL 去重状态

## Daily

Daily 自动化先运行 runner 扫描 `raw/inbox/`。如果没有 pending 且健康检查通过，只记录结果，不打扰用户。

如果存在 pending：

1. 读取 `run-result.json` 的 `pending_items`
2. 按 [[采集消化复盘SOP|采集消化复盘 SOP]] 分诊
3. 低风险内容可编译到 `wiki/`
4. 高风险内容只保留 raw source 和风险结论，不编译成可执行 SOP
5. 更新当天 `reviews/daily/YYYY-MM-DD.md`、`wiki/index.md` 和 `wiki/log.md`
6. 再运行 runner daily 和健康检查，确认幂等

## Weekly

Weekly 自动化汇总本周 daily、pending inbox、wiki/log 和健康报告。

重点：

- 合并重复主题
- 把反复出现的问题提升为 SOP、项目页或概念页
- 检查图谱是否仍直观
- 生成或更新 `reviews/weekly/YYYY-Www.md`

## Monthly

Monthly 自动化汇总当月 daily、weekly、legacy bridge 和 agentMemory 索引。

重点：

- 检查旧 `CodeXKnowledge` 哪些经验仍未编译
- 检查 `agentMemory` 项目桥接是否失效
- 检查过期结论、断链、孤立页和结构漂移
- 生成或更新 `reviews/monthly/YYYY-MM.md`

## 通知策略

- 无新增、健康检查通过：静默记录
- 有新增沉淀：输出简短结果
- 健康检查失败：输出失败原因和报告路径
- 命中敏感信息、高风险内容或无法归类：输出人工判断项

## 安全边界

- 不写入旧 `E:\CodeXData\CodeXKnowledge`
- 不写入 `E:\CodeXData\agentMemory`
- 不把 Token、Cookie、Authorization、私钥、密码、完整连接串写入 wiki 正文
- 不把高风险平台规避教程编译成可执行 SOP
